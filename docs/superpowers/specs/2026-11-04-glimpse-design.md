# Glimpse · 瞥 —— macOS 截图工具设计文档（第 1 期）

- 日期：2026-11-04
- 状态：第 1 期已实现（P1–P3，计划见 `docs/superpowers/plans/`），本文按实现后的行为同步（2026-11-05）

## 1. 目标与范围

做一个**方便、简洁、好用、界面精致**的 macOS 截图工具。常用操作一步完成，不常用的功能不出现在眼前。

**平台**：只做 macOS，最低支持 macOS 14。原生 Swift，不依赖第三方库。

**第 1 期范围**

| 功能 | 说明 |
|---|---|
| 截图 | 区域截图、窗口截图（悬停高亮，单击选中）、整屏截图（按空格） |
| 标注编辑 | 矩形、椭圆、箭头、画笔、文字、马赛克、序号；撤销/重做 |
| 输出 | 复制到剪贴板、保存 PNG |
| 贴图 | 把截图钉在屏幕上（置顶浮窗） |
| 提取文字（OCR） | 本地离线识别（Vision 框架），不调用任何外部接口，支持简体中文、繁体中文、英文 |
| 开机自动启动 | 登录项，默认开启，可关闭 |
| 日夜间 | 跟随系统外观自动切换 |

**第 2 期**：滚动长截图；截图后角落缩略图（可拖进其他应用）。

**明确不做**：已画标注的选中和再编辑（能撤销就够了）、跨屏选区、界面元素级识别（需要辅助功能权限）、云端上传、截图历史、把剪贴板里已有的图片贴到屏幕上（用截图工具栏的「贴图」按钮代替）。

**数据不落盘**：Glimpse 不保存截图历史，也没有缓存文件。冻结画面和贴图浮窗只在内存里，截图结束、关闭浮窗或退出应用就释放；复制的内容在系统剪贴板，跟平时 ⌘C 一样会被下次复制覆盖。复制时剪贴板里放的是按需编码的惰性数据（PNG / TIFF 在别的应用粘贴时才编码），Glimpse 持有的是裁剪后的独立小图，不是整屏冻结画面；因此 Glimpse 被强制结束（kill / 崩溃）后，剪贴板里的这张图会丢失，正常退出时系统会把数据落到剪贴板。硬盘上只有用户主动保存的 PNG 和几百字节的设置项。

## 2. 参考的主流交互

参考 Snipaste、微信/QQ 截图、CleanShot X、Shottr、macOS 自带截图，只借鉴通用交互习惯，界面和命名都是自己的：

- 自动识别窗口，单击选中（Snipaste）
- 放大镜：放大区中间一个「+」十字线，交叉处就是取色和定位的那个像素；下面用中文写明「位置」「颜色」（带色块），再加一行提示「按 C 复制颜色值」「按 ⇧C 复制 RGB」——一般人不知道 XY / HEX 是什么，也不知道有快捷键（Snipaste 的放大镜 + 用户真机反馈；RGB 只用于复制，不在放大镜上显示）
- 完成后给反馈：复制、保存、取色之后在屏幕正中弹一个玻璃小提示（「已拷贝到剪贴板」等），不然用户以为什么都没发生（用户真机反馈）
- **右键退一步**：编辑时右键回到重新选区，选区时右键退出（Snipaste）
- 工具栏最右边固定放 ✕ 取消 / ✓ 完成（微信/QQ）
- 提取文字可设独立快捷键，选完区域直接出文字（CleanShot X / Shottr）；默认 ⌃O，见 3.1
- 空格选中整屏、Esc 取消（macOS 自带截图）
- ⇧ 约束形状和角度；颜色和粗细全局共用、记住上次的选择，换工具不重置（微信；用户反馈「换工具又被重置了」）。进入编辑阶段时不自动选中工具，见 3.2

## 3. 交互设计

### 3.1 全局快捷键（都可在设置里自定义）

| 动作 | 默认快捷键 |
|---|---|
| 截图 | ⌘⇧A |
| 提取文字 | ⌃O |

- 默认两个全局快捷键：⇧⌘A 截图、⌃O 提取文字（和 iShot 一致）。提取文字也可以走截图工具栏的按钮或菜单栏菜单。⌃O 只对「从没设过」的用户生效：之前在设置里显式清空过提取文字快捷键的，仍然是空（`SettingsStore` 区分「没存过」和「存了空」）。
- ⌘⇧A 会盖过其他应用里的同名快捷键：Finder 的「前往应用程序」、Chrome / Edge 的「搜索标签页」。这是用户选定的取舍，介意可在设置里换。
- 全局快捷键用 Carbon `RegisterEventHotKey` 注册。它只在注册返回失败时才能发现冲突；**发现不了其他应用菜单里的快捷键，也不一定发现得了别的应用的全局快捷键**（实测：微信 4.x 的截图默认也是 ⌘⇧A，Glimpse 注册成功，但按键被微信拿走）。所以设置页除了注册失败标红，还常驻一句提示：「按快捷键没反应时，可能被微信、QQ 等应用的截图快捷键占用，请在那边改掉，或在这里换一个」；首次引导里也提一句。
- 界面上按 macOS 习惯写成 ⌃⌥⇧⌘ + 键（默认值显示为「⇧⌘A」，与 ⌘⇧A 是同一个组合）。
- 录制规则（设置页）：点按钮开始录制，按住修饰键时实时显示；单按 Esc 取消、单按 Delete 清空（右边的 ⓧ 也能清空）；不收的组合见 3.9；与另一个全局快捷键相同、或小键盘等认不出名字的键也不收，都在按钮下方红字说明。**录制期间暂停全部全局快捷键**（否则 ⇧⌘A 会被直接拿去截图），再点按钮、按键、点窗口别处、窗口失去焦点或关闭都结束录制并恢复。
- 新组合注册失败时不保存，原快捷键继续有效，红字「「⌃⌥X」已被其他程序占用，请换一个」。已保存的快捷键在启动时注册失败：保留在设置里（下次启动再试），设置页标红，菜单里不显示它。

### 3.2 截图主流程（⌘⇧A）

1. **冻结**：**先截图，后显示覆盖层**（覆盖层不会出现在截图里）。用 ScreenCaptureKit 并行截取所有屏幕的静态画面；同时用 `CGWindowListCopyWindowInfo(.optionOnScreenOnly)` 读取窗口列表，它按从前到后的层级排好序（ScreenCaptureKit 的窗口列表不保证层级顺序，不能用来判断最上层窗口）。保留 screenSaver 层级以下的所有窗口，但剔除完全透明（alpha 0）的、Glimpse 自己的普通窗口（layer 0，如设置窗口），以及盖住整块屏幕的 layer > 0 窗口（如第三方护眼 / 色调遮罩）；Glimpse 自己 layer > 0 的窗口（贴图、提取文字结果面板）留作遮挡，见 3.6；命中测试取鼠标下第一个包含该点的窗口，**仅当它是 layer = 0 的普通应用窗口时才返回**，所以 Dock、菜单栏、浮动面板挡在前面时，后面的窗口不会被吸附。然后每块屏幕弹出一个全屏覆盖层，显示冻结画面 + 55% 黑色遮罩。
2. **选区阶段**
   - 鼠标移动：高亮鼠标下最上层的窗口；鼠标下没有可吸附的窗口（桌面，或 Dock / 菜单栏 / 浮动面板挡在前面）时，高亮**鼠标所在的整块屏幕**（多屏时只高亮鼠标所在的那块）；光标旁显示放大镜（17 × 17 像素放大 7 倍，119pt 见方，最近邻采样，图像外的格子为黑色（表示「没有像素」，日夜间都是黑）；「+」十字线：一条竖线一条横线贯穿整个放大区，1pt 宽、60% 强调色，压在中心列 / 中心行正中间（7pt 格子分成 3 + 1 + 3），在中心像素上连续相交，交叉处就是取色和定位的像素；不画中心方框（用户真机反馈）；两条线互不重叠，交叉点不会叠两遍变深；下方两行左右对齐：左边次要色小字「位置」/「颜色」，右边等宽字体（`monospacedSystemFont`，十六进制的 A–F 也等宽，右对齐时不跳动）的像素坐标 / 十六进制色值，色值左边一个 12pt 圆角色块，两端与放大区左右边缘对齐；再下面两行更淡的灰色常规字重提示「按 C 复制颜色值」「按 ⇧C 复制 RGB」（并成一行要约 134pt，放不下 119pt）；不显示 RGB 数值。所有颜色随日夜间切换（文字用动态颜色，色块描边和十字线在外观变化时重画）。面板位置取整到整点（触控板的光标坐标带小数，不取整会让放大格子、十字线和文字发虚）。按 C 复制十六进制色值并退出，⇧C 复制 RGB 色值并退出，都弹 HUD「已复制颜色 #FF3B30」/「已复制颜色 255, 59, 48」）
   - Enter / ⌘C：直接复制当前高亮的内容（窗口或整屏）并关闭，HUD「已拷贝到剪贴板」；⌘S：直接保存当前高亮的内容（同时复制），HUD 同保存
   - 单击：选中当前高亮的内容（窗口或整屏），进入编辑阶段。选中窗口 = 用窗口的边框**从冻结画面里裁剪**，窗口被遮挡的部分会照原样截进来；不做单个窗口的独立截图
   - 拖拽：画出自定义选区。按下后移动不超过 3pt 算单击，超过算拖拽
   - 空格：选中整块屏幕
   - 右键 / Esc：退出
3. **编辑阶段**（选区确定后）
   - 选区四角和四边出现 8 个调整手柄，左上角上方显示尺寸标签（像素尺寸）
   - 选区下方出现工具栏，下方放不下就放到上方，再放不下就放到选区内部
   - 进入编辑阶段时**不选中任何工具**（无工具状态）
   - 无工具状态：拖动选区内部移动选区，拖手柄调整大小
   - 选了工具后：在选区内画标注，手柄仍可拖动调整大小
   - 取消当前工具：再点一次同一个工具按钮、再按一次同一个字母键，或按 Esc（见下方按键分层）
   - 方向键微调选区（每次 1pt，按住 ⇧ 每次 10pt；Retina 屏上 1pt = 2 像素），有没有选工具都可以用
   - 右键：清除选区和标注，回到选区阶段
   - 有选区时其他屏不显示悬停高亮；在其他屏单击会改选那块屏上的目标
4. **输出**
   - Enter / ⌘C / ✓：合成 → 复制到剪贴板（惰性提供 PNG / TIFF，点尺寸 = 像素 / 缩放倍数）→ 关闭 → HUD「已拷贝到剪贴板」
   - 双击选区内部：同上，**只在无工具状态下生效**（避免连点序号、画笔时误触完成）
   - ⌘S / 保存按钮：合成 → 保存 PNG（同时复制到剪贴板；PNG 只编码一次，在后台线程先写临时文件再移动到位，不覆盖已有文件，半截文件不会留在保存目录）→ 关闭 → 写成功后 HUD「已保存到「下载」」（保存目录的本地化显示名，`FileManager.displayName`），失败 HUD「保存失败，图片已拷贝到剪贴板」
   - 贴图按钮：合成（含标注）→ 关闭覆盖层 → 贴图浮窗原位出现（见 3.6）；剪贴板不动
   - 提取文字按钮：取选区原图（不含标注）→ 关闭覆盖层 → 弹出结果面板并开始识别 → 识别完成后只把文字复制到剪贴板（见 3.5）

### 3.2.1 按键分层

**选区阶段**（还没确定选区）：Esc 退出；空格选中整屏；Enter / ⌘C 复制当前高亮的内容（窗口，或鼠标所在的整块屏幕）；⌘S 保存当前高亮的内容；C 复制放大镜的十六进制色值（如 `#FF3B30`）并退出；⇧C 复制 RGB 色值（如 `255, 59, 48`）并退出；两者都弹 HUD「已复制颜色 …」。

**编辑阶段**：键盘事件按下面四层从上往下处理，上一层处理了就不再往下传：

| 状态 | 按键行为 |
|---|---|
| **正在拖画标注**（鼠标还没松开） | Esc 丢弃这一笔，工具保留；其余按键在松手前一律忽略 |
| **正在输入文字** | 所有按键都归文本框：字母（包括 R/O/A/P/T/M/N）照常输入，Enter 换行（Tab 不输入任何东西），⌘C / ⌘V / ⌘Z 以及工具栏的撤销 / 重做只作用于文本框里的文字，其他 ⌘ 组合无效；输入法组字时按键先归输入法（Esc 只取消组字）；Esc 或点击文本框外部结束输入（已输入的文字保留，空文本框直接丢弃，输入法还没上屏的组字丢弃）。点击外部（包括在另一块屏上单击）**只结束输入**，不会在点击处新建文本框或开始新选区，要再点一次才新建。输入时文本框伸出选区的部分不压暗，结束输入变成标注后才压暗 |
| **选了工具，没在输入** | Esc 取消当前工具，回到无工具状态；再按当前工具的字母键也是取消；其余按键同下一行 |
| **无工具** | Esc 直接退出；Enter / ⌘C 完成；⌘S 保存；⌘Z / ⌘⇧Z 撤销重做；单字母切换工具；方向键微调选区 |

### 3.3 工具栏

```
▢ ◯ ↗ ✎ T ▦ ① │ ↶ ↷ │ 提取文字 贴图 保存 │ ✕ ✓
```

- 鼠标悬停显示名称和快捷键（提取文字、贴图在覆盖层里没有单键，只显示名称）
- 编辑阶段单键切换工具：R 矩形、O 椭圆、A 箭头、P 画笔、T 文字、M 马赛克、N 序号（正在输入文字时不生效，见 3.2.1）
- 选中工具后，工具栏下方出现二级栏：6 个预设色 + 3 档粗细；平时不显示。颜色和粗细**全局共用**：所有工具用同一个当前颜色和同一档粗细，换工具不重置，下次截图、重启后也保留（马赛克不用颜色，只跟粗细档）。每档对应的具体尺寸仍按工具不同（如线宽、字号、马赛克笔刷）
- ⌘Z / ⌘⇧Z 撤销、重做

### 3.4 标注工具

| 工具 | 行为 |
|---|---|
| 矩形 / 椭圆 | 拖拽绘制，⇧ 约束为正方形 / 正圆 |
| 箭头 | 实心箭头，箭杆从尾部细到头部渐粗（不是等粗的直杆，用户反馈等粗不好看），箭头大小跟线宽变化，⇧ 吸附 45° |
| 画笔 | 自由绘制，路径平滑处理 |
| 文字 | 单击开始输入，回车换行，Esc 或点击别处结束（按键规则见 3.2.1） |
| 马赛克 | 涂抹区域像素化，像素取自原图 |
| 序号 | 单击放置 ①②③，自动递增，撤销时序号回退 |

### 3.5 提取文字

界面上这个功能统一叫「提取文字」（工具栏、菜单、设置、面板标题；用户真机反馈改名，原名「识别文字」，代码标识符仍用 OCR）。两个入口：截图工具栏的「提取文字」按钮（识别当前选区），或菜单栏菜单「提取文字」/ 它的快捷键（默认 ⌃O，见 3.1）。后者选区一确定（拖完松手、单击窗口或整屏、空格，或 Enter / ⌘S 取当前高亮）就直接识别，不出工具栏、不进入编辑阶段；覆盖层外观与普通截图相同，不加「识别模式」提示。识别语言跟随系统（`OCRLanguages.recognitionLanguages`，Core 里的纯函数，有测试）：取 `Locale.preferredLanguages` 里 Vision 支持的（`VNRecognizeTextRequest.supportedRecognitionLanguages()`，按语言 / 文字 / 地区就近匹配，如 `en-GB` → `en-US`、`zh-TW` → `zh-Hant`）前 3 个，简体 / 繁体任一在列就两个都加（简繁常混排），最后保证含 `en-US`；全都不支持时只有 `en-US`。accurate 模式，开启 `usesLanguageCorrection`（macOS 14 起都支持）。结果按阅读顺序拼接（按行从上到下、行内从左到右，同行用空格连接、行间换行；高度相差一倍以上的角标按中心归行，大标题旁的小字不会被吞进标题行；不做分栏检测，左右两栏按行交错读出），自动复制到剪贴板（只放文字），同时弹出结果面板：

- 识别一开始就出现，标题旁显示「正在提取…」，结果出来换成文字和「已拷贝」；没有文字显示「未提取到文字」（剪贴板不动）；出错显示「提取失败」
- 只有识别出的文字可以修改；一改动「已拷贝」消失，点「拷贝」复制当前文字并重新显示「已拷贝」（文字为空时按钮停用）
- Esc、⌘W、✕ 关闭；关闭时取消进行中的识别。只有一个面板：新的识别替换旧内容并真正取消旧的 Vision 请求；识别结束时确认没被取消、面板还开着，才写剪贴板
- 出现在选区旁边、选区所在屏上，放法同工具栏（`OCRPanelLayout`）：选区下方、右边与选区右边对齐；下方放不下放上方，都放不下盖在选区右下角内侧；最后挪进该屏可见区域、离边 8pt，原点取整。每次提取都贴着自己的选区出现，拖开只在这一次有效（用户真机反馈：面板跑到屏幕正中像是「单独弹了个窗」）；宽 440、高 300；「拷贝」按钮用界面强调色
- 和覆盖层一样是「不激活应用、但能拿键盘」的浮动面板（`.floating` 层级，不显示 Dock 图标），关掉后键盘回到原来的应用
- 新的截图 / 识别开始时，面板和 HUD、引导窗口一样先收起（进行中的识别一并取消），等一个 runloop 再截图，不会出现在冻结画面里

### 3.6 贴图浮窗

置顶、无边框、带阴影；可以同时存在多个，只在内存里，关闭或退出应用即释放。

- **出现**：从工具栏「贴图」合成（含标注）后，**原位**出现在选区的位置、原始大小（同 Snipaste），剪贴板不动。窗口大小和位置取实际裁出的像素（选区向外取整后的像素矩形），正好盖在原来的像素上
- **缩放**：滚轮 / 触控板双指滚动 / 捏合，以鼠标为中心；滚轮向前推（远离自己）放大，与「自然滚动」设置无关；甩动后的惯性滚动不缩放。范围 10%–500%，短边不小于 24pt（本来更小的图不缩小），长边不超过 10000pt；经过 100%、或朝 100% 缩到相差 3% 以内时停在正好 100%（此时窗口就是图片原尺寸），其他倍数的窗口取到屏幕像素上
- **关闭**：鼠标移到贴图上时左上角（内缩 6pt）出现一个 20pt 圆形玻璃 ✕（共用 `MaterialView`，符号用材质正文色，日夜间都看得清），移开就隐藏；第一下点击就生效，不激活应用、不让贴图拿焦点，松开时仍在 ✕ 上才关闭，走和双击相同的关闭路径。只有圆内接收点击，圆外的角仍可拖动贴图。贴图任一边小于 44pt 时不显示 ✕（会盖住大半张图、没处拖），仍可双击或右键关闭（用户真机反馈：贴完不知道怎么关）。新一次截图开始前所有 ✕ 先隐藏（有 ✕ 在屏上时和 HUD 一样等一个 runloop 再截图），不会被截进冻结画面；截图结束后鼠标下的贴图重新显示 ✕。透明度 75% / 50% 时整窗 alpha < 1，✕ 的液态玻璃会显得平一些（失去折射），接受；14 / 15 上 ✕ 用 1pt 的紧凑投影，不用面板那套 30px 柔和投影
- **其他操作**：拖动移动（系统 `performDrag`），双击关闭；右键菜单用系统 `NSMenu`（见 4.1）：复制、保存（同时复制）、透明度（100% / 75% / 50%，当前项打勾）、关闭。复制 / 保存弹 HUD（同 3.8.1）；新截图进行中才保存完时，提示等覆盖层关掉再出现
- **窗口**：不激活应用、不抢键盘的浮动面板（点它不会让当前应用失去焦点），`.floating` 层级：低于覆盖层，也低于 Dock 和菜单栏（拖到那里会被盖住，接受）；在所有桌面空间和全屏应用上都显示。拔掉显示器或调整排列后，不在任何屏幕上的贴图移回主屏可见区域的中间
- **与之后的截图**：贴图是屏幕上的普通内容，会出现在之后截图的冻结画面里（所见即所得，同 Snipaste）；窗口列表把它当遮挡：悬停时不吸附贴图，也不吸附贴图后面的窗口（鼠标在贴图上时高亮整屏），与冻结画面里看到的一致

### 3.7 菜单栏

菜单栏常驻图标，平时不占 Dock；设置窗口、引导窗口打开时显示 Dock 图标（被别的窗口挡住时能用 Dock 或 ⌘Tab 切回来），都关闭后消失，键盘回到最近一个离开的其他应用（不用 `NSApp.hide`，那会把贴图也藏起来）；提取文字结果面板不显示 Dock 图标。菜单只有：截图 ⇧⌘A、提取文字 ⌃O（设了快捷键才显示快捷键）、有贴图时多一项「关闭所有贴图 (N)」、─、设置… ⌘,、─、退出 Glimpse ⌘Q；快捷键注册失败时菜单里不显示它。不加主菜单（主菜单会在覆盖层、文字框之前截走 ⌘C / ⌘Q 等组合键），设置窗口自己处理 ⌘W、⌘Q。

**图标**：自绘的模板图（`isTemplate`，黑色绘制、系统着色，日夜间和菜单栏失活的变灰都由系统处理），18 × 18 pt，`NSStatusItem.squareLength`。六个场景：

| 场景 | 进入 | 退出 | 动效 |
|---|---|---|---|
| 空闲 idle | 其余都不成立 | — | 无 |
| 完成 done | 复制 / 保存 / 贴图成功：HUD 弹「已拷贝到剪贴板」「已保存到…」时（含贴图右键的复制 / 保存），以及贴图创建成功时；失败的 HUD 和取色不算 | 1.1 秒后自动回退；期间再次成功从头重放 | 四角收紧 0.3s（缩到 0.78 再回 1.0）；中心点像光圈一样扩散消失；✓ 从左到右画出；✓ 停 0.8s |
| 提取文字中 recognizing | `OCRController.recognize` 开始 | 识别结束（成功 / 无文字 / 失败 / 取消）或面板关闭 | 框里三行文字（y=6.5 / 9 / 11.5，x 5.5→12.5、5.5→12.5、5.5→9.5），一条扫描线（x 4.5→13.5，粗 1.2）从 y=5.5 到 y=10.7 往返，1.6s 一个循环；本趟扫描线经过的行亮（alpha 1），未经过的 alpha 0.25 |
| 有贴图 pinned(count) | 贴图数 ≥ 1 | 贴图数 = 0 | 右上角圆点 (14,4) r=2.4 弹出 0.4s（缩放 0→1，带一点回弹），之后静态；贴图数变化不重放 |
| 缺权限 needsPermission | 没有屏幕录制权限，或截图被系统拒绝（见 3.8）：启动、Glimpse 变成活跃应用、授权确认、截图发现没权限时刷新 | 下一次截图成功时清掉 | 无 |
| 录制快捷键中 recordingHotkey | 设置页开始录制快捷键（全局快捷键暂停） | 录制结束（快捷键恢复） | 中心点向外发涟漪：r 1.7→6、alpha 0.9→0，1.8s 循环 |

优先级（同时成立取第一个）：needsPermission > done > recognizing > recordingHotkey > pinned > idle。选场景（`StatusIconState.resolve`）和节奏（`StatusIconTimeline`：每个场景在第几步显示哪一帧、是否还有下一帧）都是 Core 里的纯逻辑，有单元测试；绘制和定时器在 App（`StatusIcon`、`StatusIconAnimator`）。

画法（SVG 坐标，y 向下，AppKit 里翻转）：
- 取景框四角，线宽 1.5pt、圆头、不填充：`M2 6.5 V4 A2 2 0 0 1 4 2 H6.5`、`M11.5 2 H14 A2 2 0 0 1 16 4 V6.5`、`M16 11.5 V14 A2 2 0 0 1 14 16 H11.5`、`M6.5 16 H4 A2 2 0 0 1 2 14 V11.5`
- 空闲 = 四角 + 中心实心点 (9,9) r=1.7
- 完成的 ✓：`M5.6 9.4 L8 11.8 L12.7 6.6`，线宽 1.8
- 有贴图：右上角那个角先在 (14,4) 半径 3.9 的圆内挖空（`.clear` 混合模式），再画实心点 r=2.4；其余三角和中心点照旧
- 缺权限：右下角那个角在 (13.6,13.6) 半径 5 的圆内挖空；画实心三角 `M13.6 9.6 L17.5 16.4 H9.7 Z`，再在三角里挖出感叹号（竖线 (13.6,11.3)→(13.6,13.4) 线宽 1.3 圆头，点 (13.6,15.2) r=0.75）；中心点保留
- 1x 屏线宽改 1pt（⚠ 里的感叹号也降到 1pt）、静态形状的坐标取到像素中心，避免发虚；2x 用 1.5pt。每一帧是一张带 1x 和 2x 两份位图的 NSImage，AppKit 按菜单栏所在屏的 scale 选用（多屏「显示器具有单独的空间」时各屏菜单栏都清晰），缓存键只有帧
- 动画：定时器 12 帧 / 秒换帧，每帧一张 NSImage（CGContext 现画，按场景 + 帧号 + scale 缓存），不用 Core Animation。空闲、有贴图（弹出后）、缺权限、停住的 ✓ 都没有定时器；循环动画只在对应场景期间跑
- 「减弱动态效果」（`NSWorkspace.accessibilityDisplayShouldReduceMotion`）打开时：完成直接显示 ✓ 0.8s；提取文字中显示三行静态；录制中显示静态中心点 + 一圈静态涟漪（r 4，alpha 0.4）；贴图点直接出现不弹

### 3.8 首次启动与屏幕录制权限

一个引导窗口：说明需要「屏幕录制」权限，有一个「去授权」按钮；按钮上方一行小字说明系统提示（用户真机反馈：系统提示让人不安，要先说明）：「接下来 macOS 会弹出系统提示，提到“录制屏幕和系统音频”。这是系统对所有截图工具的统一措辞；Glimpse 只在你按快捷键时截一张图，不录屏、不录音。」；需要时出现的「重新启动 Glimpse」一行；快捷键提示（同 3.1，提微信 / QQ）；下方「开机自动启动」开关（SwiftUI 小号开关，跟随界面强调色；用户还没做过选择时显示为开，表示推荐，**不注册**；点「去授权」时按开关当时的状态注册一次（之后不再推荐）；用户自己拨过开关（这里或设置页）就以拨的为准、不再推荐；做过选择后显示系统里的真实状态；红字和「打开登录项设置」按钮与设置页同一套）。无边框玻璃窗口（圆角 12），可拖动背景移动，普通窗口层级，第一次居中、之后留在原处；✕ 和 Esc 关闭（关闭后按截图快捷键会再打开）；回车对应当前主要按钮（「重新启动 Glimpse」或「去授权」）。**每次启动时没有权限都显示**，授权后自动关闭。

点「去授权」时，**先调用一次 `CGRequestScreenCaptureAccess()`**，让 Glimpse 出现在「系统设置 → 隐私与安全性 → 屏幕录制」列表里（应用从没申请过的话，列表里没有它，用户只能手动点「+」添加），再打开系统设置的这个页面。第一次点时系统会弹自己的询问框（框上有「打开系统设置」按钮），这一次不另开系统设置，免得两个窗口叠在一起。

macOS 上打开屏幕录制权限后，应用往往要**重启才生效**，所以引导窗口这样处理：

1. 引导窗口打开期间，每秒用 `CGPreflightScreenCaptureAccess()` 检查一次授权状态
2. 检测到已授权 → 关闭引导窗口，可以直接使用
3. 第一次点「去授权」（只弹系统询问框）之后，常驻一行弱提示「打开开关后若没有生效，请重新启动 Glimpse」（小字，带小号「重新启动 Glimpse」按钮）。「从系统设置回来」以 Glimpse 重新变成活跃应用为准（`NSApplication.didBecomeActiveNotification`）。此时仍检测不到授权（且之前确实打开过系统设置，只在系统询问框里点了拒绝的不算）→ 引导窗口显示「重新启动 Glimpse」按钮，点击后自动重启应用（起一个子进程，等当前实例退出、再等 0.3 秒后打开应用，最多等 10 秒，当前实例没退出就放弃；不先开新实例，否则新实例注册同一个全局快捷键会和旧实例冲突；子进程起不来时提示「无法自动重启，请手动退出后重新打开」）；重启后检测到授权就不再显示引导窗口
4. 之后授权被撤销，或系统定期再次询问时用户拒绝了（macOS 15 起系统会定期确认录屏权限）→ 下次按截图快捷键时不弹覆盖层，重新打开引导窗口
5. **截图被拒**：预检说有权限、ScreenCaptureKit 却拒绝截图（`userDeclined`）时，引导窗口直接显示「系统设置里已允许，但截图仍被拒绝。请重新启动 Glimpse；若仍不行，在系统设置里关掉再打开 Glimpse 的开关。」和「重新启动 Glimpse」。这时预检一直说有权限，轮询不会自动关窗，只能用 ✕、Esc 或重新启动关闭。截图入口仍只看预检，用户还能再试：窗口先收起再截图；截图成功时菜单栏标记立即清掉，窗口等覆盖层关掉后才正式关闭（关闭会把键盘交还之前的应用，不能抢在覆盖层还在时）；再次被拒就重新显示

授权完成后，不用打开设置页就能使用全部功能。

### 3.8.1 提示方式

所有提示都用应用自己的 **HUD 小浮层**（原计划 P3，用户真机反馈「完成后没反应，以为没存上」，提前到 P2 做）。不用系统通知，少申请一个通知权限。OCR 不用 HUD，结果面板标题处直接显示「已拷贝」。贴图右键菜单的复制 / 保存也走同一个 HUD。

- **样子**：玻璃胶囊（共用 `MaterialView`），高 36pt，左右 14pt，15pt 半粗 SF Symbol + 7pt 间距 + 13pt 中等字重一行字；失败的图标用橙色
- **位置**：截图所在的屏（有选区的那块；截图失败 / 显示器变化时取鼠标所在的屏）的可见区域（去掉菜单栏和 Dock）正中间（水平、垂直都居中），原点取整（用户真机反馈：放中间最好）
- **窗口**：独立的无边框、不激活的 `NSPanel`，`.statusBar` 层级（高于普通窗口和 Dock），加入所有桌面空间、可盖全屏应用，`ignoresMouseEvents`，不能成为 key / main，不抢原来前台应用的焦点；覆盖层关闭之后才显示，不会被覆盖层挡住。新一次截图开始前立即收起（提取文字结果面板、引导窗口同样先收起），等一个 runloop 让收起生效后再截图（截图不排除自己的窗口，不收会被截进去）。保存写完时如果已经开始了新一次截图，「已保存 / 保存失败」先记下，等那次截图关闭（完成或取消）后再显示；那次截图自己的提示（如「已拷贝到剪贴板」）会接着替换它
- **宽度**：最宽为可见区域宽度减两边各 24pt，放不下的文字中间省略
- **动画**：窗口透明度淡入淡出 0.15 秒，停留 2 秒；新提示直接替换当前这条并重新计时；「减弱动态效果」打开时不淡入淡出。同时以 HUD 面板为来源发一条 VoiceOver 播报（Glimpse 从不是前台应用，以应用为来源的播报可能被丢掉）

| 时机 | 文案 |
|---|---|
| ✓ / Enter / ⌘C / 双击完成（复制）；贴图右键「拷贝」 | 已拷贝到剪贴板 |
| 保存写盘成功（后台线程写完后回主线程；含贴图右键「保存」） | 已保存到「下载」（保存目录的显示名） |
| 保存失败 | 保存失败，图片已拷贝到剪贴板 |
| C / ⇧C 取色 | 已拷贝颜色 #FF3B30 / 已拷贝颜色 255, 59, 48 |
| 截图失败 | 截图失败 |
| 截图过程中或覆盖层显示时显示器变化 | 显示器变化，已取消截图 |

这些情况原来只有 `NSLog` + 提示音；日志保留（改走 `os.Logger`，文件路径标 `.private`、错误只记 `localizedDescription`），提示音由 HUD 取代。

- **保存目录**：显示访达里的名称和图标（「下载」），悬停显示完整路径；「更改…」以表单弹 `NSOpenPanel`（只选文件夹、可新建）。「桌面」「文稿」也有中文的访问说明。不做「恢复默认」
- **语言**：「通用」分组里的弹出框，第一项「跟随系统」（本地化），分隔线后 11 种语言各用自己的名字（不翻译）。选具体语言时往应用自己的 defaults 写 `AppleLanguages = [code]`（code 用 xcstrings 的标识：en、zh-Hans、zh-Hant、ja、ko、de、fr、es、pt-BR、ru、it），选「跟随系统」时删掉这个键；同时 `SettingsStore.interfaceLanguage` 记一份（nil / 缺省 = 跟随系统），弹出框按它显示当前值，不从 AppleLanguages 反推。文案不能热切换：选项与本次启动时的值不同时，下方出现次要色提示「重新启动 Glimpse 后生效」和填强调色的「重新启动 Glimpse」按钮（复用引导窗口的 `PermissionService.relaunch`，起不来时红字「无法自动重启，请手动退出后重新打开」）；选回与当前运行语言相同的值时提示消失。纯逻辑在 Core `InterfaceLanguage`（`system` + 11 个 case：`code`、`nativeName`、`appleLanguagesValue`、`title`）
- **开机自动启动**：状态以系统为准（`SMAppService.mainApp.status`），Glimpse 只记「用户已做过选择」：启动时不注册；首次引导窗口里开关显示为开（推荐），点「去授权」时按开关状态注册一次（失败按下面的开关失败处理），之后只由用户改（引导窗口或设置页拨过开关就算做过选择）；Debug 编译不推荐、也不在「去授权」时注册。开关失败时恢复原状并红字显示原因；系统返回「需要批准」（用户在登录项里关掉过 Glimpse）时红字「需要在「系统设置 → 通用 → 登录项」里允许 Glimpse」并给「打开登录项设置」按钮。设置窗口每次打开、Glimpse 每次变成活跃应用时重读状态，处于「需要批准」就直接显示那句红字

## 4. 视觉设计

### 4.1 材质

- **macOS 26 及以上**：Liquid Glass（AppKit `NSGlassEffectView` / SwiftUI `.glassEffect()`）
- **macOS 14 / 15**：降级为毛玻璃（`NSVisualEffectView`），圆角和布局完全一样
- 封装在 `Material` 组件里，其他界面不用关心当前用的是哪种
- **macOS 26：只用系统原生玻璃**。`NSGlassEffectView` 用 `.regular`（标准工具栏玻璃；`.clear` 用于富媒体之上，需要自己加压暗层），不设 `tintColor`，不叠任何自绘装饰：系统玻璃自带边缘高光、折射和投影。之前叠的淡色、描边、反光和投影会让玻璃发脏，投影还会从半透明的中部透出来（用户真机反馈：bar 底部中段有阴影、背景不纯、没有 26 的效果）。玻璃本身及其祖先视图（覆盖层内容视图、窗口）都不设图层遮罩、`masksToBounds`、阴影或小于 1 的透明度，免得玻璃被压成离屏绘制、退化成平的模糊
- **macOS 14 / 15：毛玻璃上按视觉稿模拟**：一层淡色（日间白 28%，夜间 rgb(40,40,48) 32%）、边缘 1px 高光描边（从左上亮到中间淡出、右下再亮一点）加 0.5px 内描边、顶部一道竖向渐隐的反光、向下 10px 的柔和投影（只在外面，不透进玻璃）；装饰都不接收点击

工具栏、颜色栏、尺寸标签、提取文字结果面板、引导窗口、HUD 统一使用这一套材质。贴图的右键菜单用系统菜单：macOS 26 的系统菜单本身就是液态玻璃，自绘还要重做键盘导航和子菜单。14 / 15 上，覆盖层里的毛玻璃模糊同一窗口里的冻结画面；提取文字结果面板、引导窗口是独立窗口，模糊窗口后面的桌面（`blendsBehindWindow`）。设置窗口用系统标准外观，不用这套材质。

### 4.2 日夜间

完全跟随系统外观，不单独做开关。

- 日间：玻璃偏白，图标深色
- 夜间：玻璃偏深，图标浅色，强调色调亮一档保证对比度
- 强调色默认跟随系统设置里选的强调色；设置页可改成固定的预设色（见 3.9），预设色取 Apple 系统色，夜间用系统色的深色值。作用于选区边框和手柄、选中按钮（底色、14 / 15 的光晕、✓）、二级栏选中色块的外圈、放大镜十字线、引导窗口的图标、「去授权」按钮和「开机自动启动」开关，以及 Glimpse 自己的窗口：设置窗口（表单 `.tint`、录制中的快捷键按钮）、提取文字结果面板的「拷贝」按钮（有文字可复制时才填色）（用户真机反馈：选了红色，设置里的开关还是蓝的）。引导窗口只有当前主要按钮（回车对应的「去授权」或「重新启动 Glimpse」）填强调色。填了强调色、带文字的按钮，文字颜色按对比度选：白字低于 3:1（WCAG 对大字和界面元素的下限，系统蓝底白字在 4:1 左右）时改用黑字，即橙、绿和夜间石墨（以及同样偏亮的系统强调色）用黑字，红、粉、紫、蓝、日间石墨用白字；图标、开关不受影响。改动立即生效：缓存了强调色的视图在 Glimpse 的选择变化或系统强调色变化时立即重画，截图途中在系统设置里换强调色也能跟上

### 5.2 数据流

```
CGImage（冻结的整屏画面，Retina 原始像素）
+ 选区（点坐标 × 屏幕缩放倍数 → 像素坐标）
+ [Annotation]（矢量标注，坐标以所在屏幕的冻结画面像素坐标存储，不相对选区）
   ↓ Renderer：先在整屏冻结画面上合成标注（马赛克从原图取像素），再按选区裁剪
最终图片 → 剪贴板 / PNG 文件 / 贴图浮窗
```

标注坐标**锚定在画面上，不跟着选区走**：编辑阶段移动选区、拖手柄缩放、方向键微调时，已画的标注停在原来的画面位置，不会和底下的内容错位。标注超出选区的部分在导出时被裁掉。

标注全程以矢量模型保存，屏幕显示和导出走同一个 Renderer，保证所见即所得，导出为 Retina 原始分辨率的不透明图片（没有 alpha 通道）。

### 5.3 多屏

每块屏幕一个覆盖层窗口；选区限定在一块屏幕内。坐标统一换算到各屏幕自己的像素坐标系，处理不同缩放倍数和负坐标。

覆盖层窗口要能盖住全屏应用和所有桌面空间：`collectionBehavior` 设为 `.canJoinAllSpaces` + `.fullScreenAuxiliary`，窗口层级设到足够高（高于菜单栏和 Dock）。

## 6. 错误处理

| 情况 | 处理 |
|---|---|
| 没有屏幕录制权限 / 权限被撤销 | 不弹覆盖层，打开引导窗口（见 3.8）；菜单栏图标显示提示标记 |
| 系统设置里显示已授权，但截图被系统拒绝（ScreenCaptureKit 报 `userDeclined`） | 不弹「截图失败」，引导窗口直接提示重新启动（若仍不行，在系统设置里关掉再打开开关）；这时检测结果一直是「已授权」，窗口不会自动关闭；菜单栏图标显示提示标记，直到下一次截图成功 |
| 截图失败（如截图过程中拔了显示器） | 关闭覆盖层，HUD 提示原因 |
| 保存失败（目录不存在 / 无写权限） | 退回到只复制剪贴板，HUD 提示 |
| 覆盖层显示时再按快捷键 | 忽略 |
| 快捷键注册失败（同一组合已被别的程序全局注册） | 录新组合时：不保存，原快捷键继续有效，设置页红字提示换一个；启动时已保存的注册失败：保留设置，设置页标红「没有注册成功，现在不可用」，菜单里不显示；其他应用菜单里的快捷键无法检测，不做提示 |
| 提取文字没识别到文字 / 识别出错 | 结果面板提示「未提取到文字」/「提取失败」，剪贴板不动 |
| 「重新启动 Glimpse」的子进程起不来 | 不退出，重启那一行换成红字「无法自动重启，请手动退出后重新打开」，响一声提示音 |
| 开机启动注册失败 | 开关恢复原状，并显示原因（「开启失败：…」）；系统要求批准时提示去「系统设置 → 通用 → 登录项」允许 Glimpse，并给「打开登录项设置」按钮。开关抛错时以系统状态为准：已经是目标状态就算成功 |

Bundle ID 暂定 `com.anglerdw.glimpse`。

**多语言**：文案源语言是简体中文（String Catalog 的 `sourceLanguage: zh-Hans`，key 就是中文原文），翻译到 en、zh-Hant、ja、ko、de、fr、es、pt-BR、ru、it，界面跟随系统语言。开发区域（project.yml `developmentLanguage: en` → `CFBundleDevelopmentRegion`；Core `defaultLocalization: "en"`）是英文：系统语言不在这 11 种之内（荷兰语、越南语等）时回退英文，而不是中文。三份 xcstrings 由 `scripts/i18n/generate_xcstrings.py` 从 `scripts/i18n/strings.json` 生成，不手改。

**构建要求**：Xcode 26 及以上（需要 macOS 26 SDK 才能编译 Liquid Glass 接口）；部署目标 macOS 14。Liquid Glass 相关代码都包在 `if #available(macOS 26, *)` 里，其余版本走毛玻璃分支。

## 8. 测试

**单元测试（swift test）**
- 坐标换算：Retina 2 倍屏、外接 1 倍屏、多屏负坐标；`CGWindowListCopyWindowInfo` 的坐标（主屏左上角为原点）与 AppKit 坐标（左下角为原点）互转
- 标注锚定：画好标注后移动 / 缩放选区，标注在画面上的位置不变，超出选区的部分导出时被裁掉
- 窗口命中：给定按层级排序的窗口列表和鼠标位置，取第一个包含该点的窗口，仅当它是 layer = 0 窗口时返回
- 按键分层：各状态下的按键路由（3.2.1 的表格逐条转成测试用例）
- 选区：拖拽、手柄调整、方向键微调、边界限制
- 撤销重做：含序号回退
- 合成：固定输入图 + 标注，与基准图逐像素比对
- OCR 排序：中英混排样图，验证阅读顺序
- 设置读写、强调色预设、快捷键录制规则与显示
- 引导窗口「重新启动」的显示时机（`PermissionFlow`）
- 菜单栏图标场景的优先级（`StatusIconState`：缺权限 > 完成 > 提取文字中 > 录制快捷键中 > 有贴图 > 空闲，贴图数 0 / 1 / n）
- 贴图缩放：范围、停在 100%、以鼠标为中心、取整到屏幕像素
- 提取文字结果面板位置（下方 / 上方 / 选区内、挪进可见区域、负坐标副屏、选区伸进菜单栏）；强调色填色按钮的文字颜色（WCAG 对比度）；HUD 位置（可见区域正中）；贴图 ✕ 的位置与小贴图不显示

- 多显示器（不同缩放倍数）：提取文字结果面板出现在选区所在屏，贴图原位出现

- 快捷键录制（含被拒的组合、注册失败）、强调色立即生效、保存目录更改
- macOS 14 / 15 毛玻璃降级、macOS 26 液态玻璃
- 开机自动启动开关（用放进 /Applications 的那份 .app 测，重启电脑验证；从 Xcode 的 DerivedData 运行时路径会变，结果不可靠）；Debug 编译不会自动登记登录项，默认开启只在 Release 版第一次运行时生效
- 多个贴图浮窗同时存在
